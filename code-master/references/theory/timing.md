# 时序约束：四条

任何链路都被四条时序约束同时作用——它们不是分立的规则，而是同一时间观的不同侧面：

**1. 依赖前向包含。** 被依赖方的生命周期必须**前向包含**依赖方使用它的时间窗。否则就会出现「用到一个已销毁的对象」「竞争一个未初始化的对象」等时序错位。这是单向依赖约束的根源——一旦允许反向，前向包含就不可能被满足。

**2. 空间封装 = 短暂生命周期。** 空间（文件 / 函数 / 类 / 进程）有生命周期，且生命周期是**短暂的**——离开作用域即销毁。状态住在空间之中，而**状态本身没有生命周期**（状态是逻辑概念，不是物理对象）。把状态封装在空间里，是状态机复杂度的核心机制：状态机的状态总数 = 各空间内状态的并集。

**3. 逻辑时序需求。** 需求中明确指定的时序约束——「先 A 再 B」「B 失败则回滚 A」「C 与 D 并发」。这些是**需求层**的约束，必须直接落到代码里，不能用「自然会发生」替代。

**4. 工程管理约束。** 单项目工程管理带来的硬约束——模块路径、命名空间、编译单元、依赖可见性。这些不是逻辑需求，但违反它们 = 工程失败（编译不过、循环 import、可见性错误）。

> **先有空间再有时间。** 空间决定了时间的可能——能存活多久、能跟谁对话、能产生什么状态。先想清楚空间布局，时序自然就有了；反过来从时序反推空间，几乎必然导致反复重构。
