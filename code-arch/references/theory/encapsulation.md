# 复杂度封装效应

复杂度的真正机制是「**封装**」——而不是「消灭」。

| 复杂度来源 | 封装在哪 | 封装手段 |
| --- | --- | --- |
| 状态数爆炸 | 模块边界 | 模块内聚 + 模块间接口 |
| 转移函数膨胀 | 函数 / 方法 | 单一职责 + 行为拆分（rust-style R2 / ts-style R2） |
| 时序错综 | 生命周期契约 | 显式 `init` / `destroy`（rust-style R3 / ts-style R4–R5） |
| 副作用失控 | 副作用边界 | IO / 状态机分离；`connect` / `close` 显式管理（rust-style R3 / ts-style R4–R5） |

> 封装不是「把复杂度藏起来」——是「把复杂度装进**有边界的、可命名的、可测试的**空间」。藏起来的复杂度会反弹；装进边界的复杂度能管理。
