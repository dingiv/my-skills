# 自查清单

完成架构设计的每个里程碑时，对照自查：

## 步骤 1（需求）

- [ ] 需求拆成了 N 条端到端链路（而不是功能列表）？
- [ ] 每条链路都标了触发点 + 输入 + 输出 + 终止条件？
- [ ] 链路之间没有未声明的耦合（「A 触发 B 但没说」「B 依赖 A 的内部状态」）？

## 步骤 2.1（入口 / 空间）

- [ ] 入口唯一（即使内部多入口，外部触发点收敛）？
- [ ] 状态、依赖、配置都从入口注入？
- [ ] 空间布局（模块 / 文件 / 进程）由入口驱动，而不是反过来？

## 步骤 2.2（接口）

- [ ] 接口由链路需求驱动（不是由实现驱动）？
- [ ] 接口用伪代码定义（先定义契约，再写实现）？
- [ ] 接口的生命周期（`init` / `destroy`）写进了契约？

## 步骤 2.3（依赖 / 时序）

- [ ] 依赖图是单向的（无循环）？
- [ ] 每个依赖都能回答「它的生命周期覆盖到哪里」？
- [ ] 时序约束（先 A 再 B、B 失败回滚 A、C∥D 并发）都有明确落点？

## 步骤 2.4（空间优化）

- [ ] 每个模块都满足单一职责（只做一类事、且仅在一处做）？
- [ ] 每个能独立 `init` / `destroy` 的子单元都被拆了？
- [ ] 拆完以后依赖图的深度和广度都降低了（而不是文件多了但依赖没变浅）？
