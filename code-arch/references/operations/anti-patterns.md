# 典型反模式

| 反模式 | 表现 | 纠正 |
| --- | --- | --- |
| **需求当功能列表** | 「系统应当支持 X」 | 改成端到端链路：触发 + 输入 + 终止 |
| **入口不唯一** | 多处都能启动同一条链路 | 收敛到唯一入口；其它走内部调用 |
| **接口由实现驱动** | 先写实现、再抽接口 | 反过来：先画链路、再定接口契约、再写实现 |
| **依赖图有环** | A 依赖 B、B 依赖 A | 找出循环点，抽接口或上提公共依赖 |
| **空间布局先于需求** | 先分模块、再想怎么用 | 反过来：先有链路、再按链路落模块 |
| **拆分等同于文件数** | 把代码拆成 N 个文件就以为拆完了 | 看依赖图：深度广度都降了才叫拆完 |
| **时序用「自然会发生」** | 「B 一定在 A 之后执行」 | 写进契约：要么显式 init 顺序，要么显式状态依赖 |
| **架构不写下来** | 「架构在我脑子里」 | 写下来——AI 的上下文、人的沟通、未来的自己都需要 |
